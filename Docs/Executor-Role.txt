Q. What jobs does the Executor service instaces actually carry out?

=> initially i will make the executers do the job (business logic ) themselves until my system is completely working, after that i will modify them accordingly later like instead of performing business logic create a container and hand over it the job, or make external api calls



Q. Will it need changes in the databse schema with the evolution of the executor service?

=> Since the DB is like this 

Job DB

    jobs table :

        - id (index)
        - name
        - schedule_type
        - status (paused/scheduled/cancel)
        - schedule_time (partition)
        - cron_expression
        - payload
        - retires 
        - meta


    job_runs table :

        - id
        - job_id (index)
        - status (index) (queued/running/success/failed)
        - start_time
        - end time
        - modification_time (index)    note:- composite index on [status + modification_time]
        - attempt_number
        - error_msg



With the evolution we will not need to make changes in the schema as if we add new features we can mention them in the payload field and the executor will pase it accordingly and perform the job. So we can keep the schema as it is for now.

So the design decison is finalized : For the executor service i will follow the evolutionary design pattern and will not make any changes in the schema for now.
